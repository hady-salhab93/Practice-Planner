# Agree on feature boundaries and discovery order

## Question

Given the [approved minimum useful practice-and-review loop](first-useful-version.md), which distinct user outcomes should become separately grilled features, and in what order should their decisions be explored? Compare material collection and breakdown, Sprint planning and refinement, focused timing, daily observations, and Sprint review as candidates, not an approved feature list. This establishes discovery boundaries rather than implementation order or detailed behavior.

## Resolution

The user approved these five feature boundaries and their discovery order on 2026-10-11:

| Order | Feature | User Outcome | Opening Discovery Question |
| --- | --- | --- | --- |
| 1 | Manage practice material and breakdown | Keep material and divide it into actionable pieces. | What must be captured and how should material be broken down to prepare useful practice? |
| 2 | Plan and refine Sprints | Commit to a focus, adjust it, and prepare the next round. | How does the user choose, maintain, and refine a Sprint's commitment? |
| 3 | Time focused practice | Record attention against the piece being practiced. | What timing workflow and recovery behavior make the practice record trustworthy? |
| 4 | Record optional daily observations | Capture reflections that help explain the practice record. | How are daily reflections captured, edited, and made available for review? |
| 5 | Review a Sprint | Understand where time went and decide what to focus on next. | What record and comparisons support the user's end-of-Sprint decisions? |

All five belong to the approved minimum useful loop. This is an interview order, not implementation order or a claim that one feature technically blocks another.

The application-level discovery map is complete. Begin the next stage with the material-management interview, confirm shared understanding, then write its feature PRD and decompose approved behavior into implementation issues. Repeat for the remaining features in this order. These opening questions are handoff prompts, not approved detailed behavior or implementation tickets.
